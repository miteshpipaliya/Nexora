7. WP6: ADMIN PASSWORD SAYS INCORRECT AFTER RESTART (R6)
Symptom: the founder sets a password, the app restarts (a new serverless instance), and the same password is rejected. Treat it as a persistence or comparison bug until proven otherwise.
1. Write a failing test first: create two separate app instances that share one fake Firestore; set the password on instance A; verify the same password on instance B. It must fail before your fix and pass after.
2. Find the root cause with evidence. Candidates: (a) the write is not awaited or is swallowed by an empty catch, but setup still returns success; (b) setup writes and login reads different databases or documents (the app uses the NAMED Firestore database, not the default one; the document is _admin_security/founder); (c) the environment variable ADMIN_SECURITY_PASSWORD still exists in Vercel and takes precedence, so the typed password is compared with the old value; (d) hash, salt, encoding or scrypt parameters differ between setup and verify, or the password is trimmed, normalised or changed by JSON parsing or by the client on one path only; (e) cached in-memory state (initialized flag, passwordVersion, sessionsRevokedBefore) rejects a valid password after restart; (f) a rate-limit lockout or a Firestore read error is reported with the same message incorrect password.
3.
